## 1. Постановка была неверна в одном месте — исправлено правильно

ТЗ, §2.4: «блочный бутстрап с блоком ≥ 96 баров». Это ошибка на порядок, и исполнитель её нашёл.

Бутстрап переставляет **строки выборки**, а кандидаты идут не на каждом баре. Блок в 96 строк накрыл бы ≈ 1046 баров — вдесятеро больше горизонта, и тест стал бы абсурдно консервативным. Правильный перевод — через фактическую плотность:

```
шаг строки = (ts.max − ts.min) / (n − 1) = 163.5 мин
длина блока = 1440 / 163.5 ≈ 8.8 → 9 строк
```

Совпадение с `DEFF ≈ 8.8` из постановки не случайно: это одна и та же величина, посчитанная с двух сторон. Реализация верна, постановка была нет.

## 2. Технические дефекты реализации

Три штуки, все в `btcproc/analysis/lift.py`. Ни одна не отменяет полученные выводы, но каждая смещает их в известную сторону.

### 2.1. Разрешения бутстрапа не хватает под Бонферрони (пункт B)

`DEFAULT_N_BOOT = 2000`, p-value с поправкой на единицу: `p = (1 + k) / (1 + B)`, минимум `1/2001 ≈ 0.0005`.

Порог Бонферрони при 25 тестах: `0.05 / 25 = 0.002`. Значит пройти могут только `1 + k ≤ 4.002`, то есть **не более трёх реплик из двух тысяч** вправе превысить наблюдённый лифт.

Насколько это шумно. Если истинная хвостовая вероятность `p = 0.001`, ожидаемое `k` в 2000 репликах равно 2, распределено пуассоновски:

```
P(K ≤ 3 | λ = 2) = e⁻²·(1 + 2 + 2 + 8/6) = 0.1353 × 6.333 = 0.857
```

То есть **14% шанс потерять настоящий эффект** просто на шуме Монте-Карло, независимо от данных.

Починка — любая из двух:
- `n_boot ≥ 20000` при использовании Бонферрони. Правило: `n_boot ≥ 10 · m / α`;
- либо дефолтная поправка меняется на BH, где порог мягче и разрешения 2000 хватает.

Рекомендуется первое для решающих замеров, второе — для разведочных. В `format_table` добавить предупреждение, если `1/(1+n_boot) > α/m · 0.25`.

### 2.2. Длина блока считается от среднего шага (пункт C)

`block_length_rows` берёт `(ts.max − ts.min) / (n − 1)` — средний интервал по всей выборке. Но плотность кандидатов по истории **неоднородна**, и это задокументировано в этом же проекте: ранняя история реже, поздняя плотнее; снимки офсетов `(0, 45, 90, 180)` дают четыре кандидата в пределах 12 баров, потом разрыв.

Зависимость сильнее всего там, где плотность выше. Средний шаг завышает интервал в плотных участках, значит блок оказывается короче нужного, значит тест анти-консервативен ровно там, где должен быть строже.

Починка: считать шаг по нижнему квантилю фактических интервалов, а не по среднему.

```python
gaps = ordered.diff().dropna().dt.total_seconds() / 60.0
step_minutes = float(gaps.quantile(0.10))   # плотные участки
```

Побочно даст более длинный блок и более консервативный тест — направление правильное.

Проверка: `thinned_z` уже реализован и от этой ошибки свободен (окна нарезаются по времени, а не по строкам). Расхождение бутстрапа и прореживания — прямой индикатор проблемы. На тестовых данных они согласуются; надо сверить на боевых.

### 2.3. Непригодные реплики смещают p вниз (пункт D)

```python
usable = (counts > 0) & (counts < n)
extreme += int((usable & (lifts >= observed)).sum())
done += size          # ← считает ВСЕ реплики, включая непригодные
```

Непригодная реплика (все флаги True или все False) попадает в знаменатель, но никогда в числитель. Смещение — вниз, то есть в сторону значимости.

Для частого атома доля непригодных пренебрежима. Для самого редкого, проходящего `min_group = 30` при `n ≈ 28 800`, доля True около 0.1%, блоков с True около 3.2 — доля реплик без единого True порядка `e^-3.2 ≈ 4%`. То есть до 4 процентных пунктов относительного смещения **у самых редких атомов, которые и без того наиболее подозрительны**.

Починка: `done += int(usable.sum())`, добирать реплики до нужного числа пригодных.

## 3. Блокер выката: 51 состояние против 43 (пункт A)

### 3.1. Что произошло

Калибровка выбрала `sigma = 2.0` по критерию, зафиксированному заранее: минимальный разброс числа состояний между окнами разной длины. Критерий соблюдён честно, значение выбрано не под «сколько было раньше» — всё правильно.

Но порог `2σ ≈ 0.01` оказался **мягче** прежнего абсолютного `0.02`, и BTC даёт 51 состояние вместо 43.

### 3.2. Чего критерий калибровки не учитывал

Инвариант I5 из первого ТЗ по SMC: доля `scope = transition+event_block` не ниже 20%. Фактическая была 29.3% при 43 состояниях.

Механизм: больше состояний → больше различимых переходов → каждый переход реже → `sample_size` по ключу `(transition_id, event_block_id)` падает → чаще срабатывает откат `CAND_FALLBACK_TRANSITION` при `sample_size < 30`.

Оценка сверху. При 43 состояниях наблюдался 631 переход, то есть 35% от `43 × 42 = 1806` возможных упорядоченных пар. При 51 состоянии пар `51 × 50 = 2550`; при той же плотности заполнения — около 890 различимых переходов, рост в 1.4 раза. Число самих смен состояния тоже растёт (более дробное разбиение пересекается чаще), но линейно, а не квадратично.

Итог: доля полного ключа почти наверняка упадёт. Насколько — надо мерить, а не оценивать.

**Прежде чем выкатывать**, прогнать `train --all --no-emit` на sigma = 2.0 и снять `runs.stats.candidates.scopes`.

## 4. `premium_discount` — единственная живая ниточка (пункт E)

Не засчитан по предзаявленному критерию: профиль по бинам не строго монотонен, одна инверсия. Корреляция с `pos_1d` = 0.44 — дубликатом существующего признака не является.

### 4.2. Почему это интереснее, чем выглядит

Критерий проверял монотонность **по бинам признака**. А данные показывают монотонность в другом измерении — **по таймфрейму**, и это ровно та зависимость «доза — отклик», которую предсказывает гипотеза «зоны работают, но не на 15-минутке».

Это независимое свидетельство, и в предзаявленный критерий оно не входило. Что означает: **промотировать его сейчас нельзя** — это в точности сад расходящихся тропок. Гипотеза породилась данными и должна быть проверена на данных, которые её не порождали.

### 4.3. Как проверить честно

Гипотеза формулируется как **количественное предсказание, сделанное до замера**:

> Если эффект растёт с таймфреймом, то на D1 лифт `premium_discount` будет отрицательным и по модулю больше 0.084.

Это фальсифицируемо и требует одного прогона. Порядок:

1. Записать предсказание в `development_log.md` **до** запуска, с датой и числом.
2. Прогнать `measure_zone_timeframe.py` с добавленным D1 по трём монетам.
3. Засчитать только при выполнении: знак отрицательный, `|лифт| > 0.084` на BTC, и знак сохранён на ETH и SOL.

Что засчитывать нельзя ни при каком раскладе: «на D1 меньше, но всё равно значимо» — это уже не та гипотеза.

Дополнительно проверить инверсию бинов: если она приходится на крайний бин с малым `n`, это артефакт выборки, а не нарушение монотонности. Посмотреть `n` по бинам.

## 5. Поток C неисполним на этих данных — расчёт (пункт F)

Прежде чем тратить время на условные тесты, надо посчитать, что они в принципе могут обнаружить.

Эффективное число независимых наблюдений: `n_эфф = 314 141 / 96 ≈ 3272` на монету.

Минимальный обнаружимый лифт при `z = 2.5`, `p ≈ 0.5`:

| Частота конъюнкции | n₁ | n₂ | SE | Нужен лифт |
|---|---|---|---|---|
| 2% | 65 | 3207 | 0.0627 | **0.157** |
| 5% | 164 | 3108 | 0.0401 | **0.100** |
| 10% | 327 | 2945 | 0.0291 | **0.073** |
| 20% | 654 | 2618 | 0.0219 | **0.055** |

Расчёт для 5%:
```
SE = √( 0.25 × (1/164 + 1/3108) ) = √( 0.25 × 0.006422 ) = √0.001606 = 0.0401
лифт = 2.5 × 0.0401 = 0.100
```

Наблюдаемые в системе эффекты — 3–8 процентных пунктов. Конъюнкция из четырёх практических условий имеет частоту порядка 1–3%.

**Вывод: конъюнкции реже ~10% на этих данных непроверяемы в принципе.** Не «трудно проверить» — математически невозможно отличить от нуля. А конъюнкции частотой 20% и выше не являются тем, что имеет в виду практика SMC.

Это не аргумент против гипотезы. Это аргумент о том, что данных не хватает, и он указывает на три выхода:

## 7. Амплификация пограничных решений: лечение есть, ингредиент измерен (пункт H)

Замер исполнителя: на крупных группах BTC `gain` по восьми подвыборкам даёт `+0.032 ± 0.007` (решение «дробить» 8 из 8) и `−0.019 ± 0.010` (1 из 8). Вывод сформулирован верно: критерий воспроизводим вдали от границы и переворачивается у неё, а рекурсия усиливает единственный перевёрнутый выбор во всё поддерево.

Но лечение при этом уже посчитано и не применено. **Голоса есть — надо на них решать, а не на одном draw.**

Ансамблевое решение о дроблении:

```python
def _split_vote(x, rng, cfg) -> bool:
    """
    Дробим, если за это голосует большинство подвыборок силуэта.

    Одна подвыборка у границы решения переворачивается, а рекурсия
    усиливает единственный перевёрнутый выбор во всё поддерево. Голосование
    убирает именно этот механизм: устойчивое решение проходит единогласно
    (замер 2026-08-11: 8/8 при gain +0.032), пограничное отсеивается (1/8
    при −0.019).
    """
    votes = sum(
        _split_gain(x, np.random.default_rng(cfg.random_state + k), cfg) > 0
        for k in range(cfg.split_vote_draws)
    )
    return votes >= cfg.split_vote_threshold * cfg.split_vote_draws
```

Параметры: `STATES_SPLIT_VOTE_DRAWS = 5`, `STATES_SPLIT_VOTE_THRESHOLD = 0.6` (три из пяти).

Стоимость. Сейчас одна кластеризация 2.3 минуты. Голосование по 5 подвыборкам умножает, но число референсов можно снизить с 10 до 4 — голосование уже усредняет, и точность каждой отдельной сигмы менее важна. Чистое удорожание ≈ 2× вместо 5×, то есть ~5 минут на монету.

Ожидаемый эффект: разброс числа состояний падает у всех монет, включая SOL, потому что убирается именно тот механизм, который его порождает. Это стоит проверить **до** того, как лезть в `states_overrides` SOL руками: если голосование лечит, отдельная задача по SOL не понадобится.

Порядок: реализовать → прогнать калибровочный свип заново (он уже автоматизирован) → сравнить разбросы с текущими 10.3% / 13.9% / 41–50%.

| Ордер-блоки (`in_bullish_ob`) | p = 0.11 | не прошёл | не прошёл | Отвергнут трижды |
| Брейкеры (`in_breaker`) | p = 0.91 | не прошёл | не прошёл | Отвергнут трижды |
| Снятия ликвидности | — | не прошёл | не прошёл | Отвергнут |

Отдельно: `corr(in_discount, in_premium) = −0.642` подтверждено фактом — зеркальная пара, в поправку входит как одна гипотеза.

Прогноз §9 прежнего ТЗ («большинство из четырёх атомов отвалится, `bos_down` имеет лучшие шансы») сбылся наполовину: отвалились трое из четырёх, но уцелел не `bos_down`, а `structure_bullish`. Прогноз владельца проекта («вероятнее всего вылезет в потоке A») не подтвердился — поток A не дал ничего ни на одной монете, то есть бинаризация не была причиной нуля.

**Что это означает содержательно.** Три независимые операционализации зонной SMC дали ноль. Это уже не «замер был слабый» — это устойчивый отрицательный результат по ордер-блокам, имбалансам и брейкерам на данном горизонте и данных инструментах. Оставшиеся живые линии — структура рынка и позиция в диапазоне, то есть ровно те две вещи, которые в SMC пересекаются с классическим тренд-следованием и возвратом к среднему.

Атомы при этом **остаются включёнными**: они контекстные, блоки не дробят, переобучения не требуют и полезны для разметки и разбора независимо от лифта.
