## 12.1. Почему наивная статистика здесь врёт

Возьмём типичный вопрос: «даёт ли атом `volume_spike` сдвиг в исходах?»

Наивное решение: разделить кандидатов на две группы, посчитать доли успеха и
применить двухвыборочный z-тест:

$$p_{\text{pool}} = \frac{p_1 n_1 + p_2 n_2}{n_1 + n_2}, \qquad
\text{SE} = \sqrt{p_{\text{pool}}(1 - p_{\text{pool}})
\left(\frac{1}{n_1} + \frac{1}{n_2}\right)}, \qquad
z = \frac{p_1 - p_2}{\text{SE}}$$

Формула верна **только для независимых наблюдений**. Здесь они зависимы дважды.

### Источник 1: перекрытие горизонтов

Горизонт 24 часа при базовом ТФ 15 минут — это 96 баров. Два кандидата,
отстоящие меньше чем на 96 баров, имеют почти один и тот же исход: их окна
перекрываются.

По фактическим числам BTC (314 141 бар, 28 818 кандидатов одной модели) в одно
окно горизонта попадает **около девяти кандидатов**.

### Источник 2: снимки офсетов

`SNAPSHOT_OFFSETS_MIN = (0, 45, 90, 180)` даёт до четырёх кандидатов на одну
реализацию перехода в пределах 12 баров — с перекрытием окон 87.5% и выше.

### Цена ошибки

Эффективный размер выборки при кластеризованных наблюдениях:

$$n_{\text{эфф}} = \frac{n}{\text{DEFF}},
\qquad \text{DEFF} = 1 + (\bar{m} - 1)\rho$$

где $\bar{m}$ — средний размер кластера зависимых наблюдений, $\rho$ —
внутрикластерная корреляция. При $\bar{m} \approx 9$ и высокой $\rho$
получается $\text{DEFF} \approx 9$, то есть

$$\text{SE}_{\text{истинная}} = \text{SE}_{\text{наивная}} \cdot \sqrt{\text{DEFF}}
\approx 3 \cdot \text{SE}_{\text{наивная}}$$

**Наивный $z$ завышен примерно втрое.** Тест анти-консервативен: он находит
эффекты, которых нет.

### Асимметрия, которую важно понимать

Отрицательный результат от починки становится только **надёжнее**: не прошло при
завышенном $z$ — не пройдёт и при честном. Положительный требует перепроверки.

Это свойство активно используется: часть выводов проекта получена ещё наивным
тестом и от перехода на честный не пострадала.

Поэтому каждый результат в системе несёт **два** p-value: наивный (ради
сопоставимости со старыми замерами и чтобы разница была видна глазами) и
бутстрапный. Значимость определяется по второму.

## 12.2. Стационарный блочный бутстрап

### Идея

Обычный бутстрап пересобирает выборку по одному наблюдению — и разрушает
автокорреляцию, то есть моделирует ту самую независимость, которой нет.

Блочный бутстрап пересобирает **блоками** подряд идущих наблюдений: внутри блока
структура зависимости сохраняется.

Реализован вариант **Полица–Романо** (stationary bootstrap): длина блока не
фиксирована, а геометрически распределена со средним $b$.

$$P(\text{длина блока} = k) = (1 - p)^{k-1} p, \qquad p = 1/b$$

Почему геометрическая, а не фиксированная: при блоках постоянной длины
распределение реплики зависит от того, куда попали границы блоков; реплика
перестаёт быть стационарной. Геометрическая длина эту зависимость снимает.

### Векторная реализация

```python
def stationary_block_indices(n, block_length, rng, size):
    p_block = 1.0 / max(block_length, 1)
    starts    = rng.integers(0, n, size=(size, n))
    new_block = rng.random((size, n)) < p_block
    new_block[:, 0] = True

    positions = np.arange(n)
    block_id  = np.cumsum(new_block, axis=1) - 1
    start_pos = np.maximum.accumulate(np.where(new_block, positions, 0), axis=1)
    offset    = positions - start_pos
    return (np.take_along_axis(starts, block_id, axis=1) + offset) % n
```

Возвращается матрица $(\text{size}, n)$ индексов — сразу все реплики чанка.
Питон-цикл по $n$ на каждую реплику съел бы минуты на каждый атом.

Размер чанка подбирается по объёму памяти:

```python
CHUNK_CELLS = 2_000_000
chunk = max(1, min(n_boot, CHUNK_CELLS // max(n, 1)))
```

На 30 тысячах кандидатов это ~66 реплик за проход, около 16 МБ на массив int64.

### Длина блока: единственное место, где легко ошибиться на порядок

Зависимость возникает **во времени** (перекрытие горизонтов), а бутстрап
переставляет **строки** кандидатов. Одно в другое переводится не единицей:
кандидаты идут не на каждом баре.

Считается ровно та величина, которой блок и обязан быть равен: **среднее число
строк, попадающих в одно окно горизонта**.

```python
right = np.searchsorted(minutes, minutes + horizon_minutes, side="left")
per_window = right - np.arange(n)
complete = minutes + horizon_minutes <= minutes[-1]
# если строк с полным окном нет — выборка короче горизонта, берём что есть
sample = per_window[complete] if complete.any() else per_window
length = int(round(float(sample.mean())))
return max(2, min(length, max(2, n // 10)))
```

Это и есть $\bar{m}$ из формулы DEFF.

Два неверных способа, которые пробовались:

**Через средний шаг между строками** (было до 2026-08-11). Распределение
интервалов сильно скошено: у BTC медиана 45 минут (это шаг снимков офсетов —
соседние строки чаще всего описывают один переход), а среднее 126 минут, потому
что его тянут вверх редкие участки ранней истории. Деление горизонта на средний
шаг давало 11 строк при фактических 14.8 — блок короче нужного на треть, тест
анти-консервативен.

**По нижнему квантилю интервалов.** Проверено замером: `p10` интервалов у всех
трёх монет равен 30 минутам, что дало бы блок в 48 строк — перелёт втрое в другую
сторону. Квантиль интервалов оценивает плотность самого тесного места, а не
плотность окна.

Отдельно: у последних строк окно обрезано концом выборки, и их усреднение
занижало бы длину блока (на плотном ряду из 2000 строк — 94 вместо 96). Считаются
только строки с полным окном.

Границы: не меньше 2 (блок в одну строку = обычный бутстрап, то есть отсутствие
поправки) и не больше $n/10$ (иначе блоков слишком мало, чтобы их перестановка
что-то давала).

### Нижняя граница по автокорреляции предиктора

Для предикторов с собственной памятью длиннее горизонта блок по горизонту
занижен. Пример — Fear & Greed: дневной ряд, 96 одинаковых значений подряд,
автокорреляция 125 дней.

```python
def autocorr_block_rows(daily_values, bars_per_day, floor=0.2, max_lag_days=400):
    for lag in range(1, max_lag_days + 1):
        r = series.autocorr(lag=lag)
        if abs(r) < floor:
            return lag, lag * bars_per_day
    return max_lag_days, max_lag_days * bars_per_day
```

Первый лаг, на котором автокорреляция падает ниже 0.2. Итоговая длина блока:

$$b = \max\left(b_{\text{горизонт}},\ b_{\text{автокорреляция}}\right)$$

Для FGI это дало `--block-rows 12000` вместо ~15.

## 12.3. Как воспроизводится нулевая гипотеза

Здесь тонкость, определяющая корректность теста: **что именно пересобирается**.

### Двухвыборочная задача: пересобирается признак

Вопрос: «связан ли атом с исходом?» Нулевая гипотеза: связи нет.

```python
idx = stationary_block_indices(n, block_length, rng, size)
resampled = flags[idx]          # пересобирается ПРИЗНАК
# метрика остаётся на месте
lifts = np.abs(mean_with - mean_without)
```

Блоками пересобирается **признак**, метрика остаётся на месте. Это принципиально:
обычный `shuffle` признака разрушил бы его автокорреляцию («атом держится
сериями») и вернул нас к наивному тесту другим путём. Блочная пересборка
сохраняет автокорреляцию **обоих** рядов, ломая только их взаимное выравнивание.

### Одновыборочная задача: пересобирается сам ряд

Вопрос: «отличается ли accuracy от 0.5?» Нулевая гипотеза касается уровня одной
величины.

```python
means = values[idx].mean(axis=1)     # пересобирается сам ряд значений
```

### Сравнение двух предикторов: пересобираются строки целиком

Вопрос: «сильнее ли A, чем B, на одной цели?» Пара предикторов привязана к одному
бару.

```python
ra = _row_pearson(rank_a[idx], rank_t[idx])   # a, b и target вместе
rb = _row_pearson(rank_b[idx], rank_t[idx])
not_better += np.sum(np.abs(ra) <= np.abs(rb))
```

### Поправка на единицу

$$p = \frac{1 + k}{1 + B}$$

где $k$ — число экстремальных реплик, $B$ — их общее число.

Без поправки нулевой p-value выглядел бы как «эффект достоверен абсолютно», хотя
означает лишь «реплик не хватило».

### Только пригодные реплики в знаменателе

Реплика, у которой все флаги оказались `True` или все `False`, лифта не даёт
вовсе — она не может попасть в числитель ни при каких данных. Считая её в
знаменателе, мы занижали бы $p$, то есть смещали результат в сторону значимости.

Для частого атома доля таких реплик пренебрежима, а для самого редкого,
проходящего порог `min_group = 30` при $n \approx 30\,000$, — порядка процентов.
Смещение попадало бы ровно на те атомы, которые и без того наиболее
подозрительны.

```python
usable = (counts > 0) & (counts < n)
extreme     += int((usable & (lifts >= observed)).sum())
usable_total += int(usable.sum())
```

Реплики добираются до нужного числа **пригодных**, с потолком на число попыток:
у вырожденного входа их может не набраться никогда.

## 12.4. Множественные сравнения

Тестируется не один атом, а все 29 (или 45 с включёнными источниками). При
$\alpha = 0.05$ и 29 тестах полтора «значимых» результата появятся из чистого
шума.

Без поправки замер находит SMC-паттерны там, где их нет — ровно та ошибка,
из-за которой они «работают» на бэктесте.

### Бонферрони

$$\text{отвергаем } H_i \iff p_i \le \frac{\alpha}{m}$$

Самая консервативная поправка, контролирует FWER.

### Бенджамини–Хохберг

При $m > 20$ Бонферрони становится настолько строгим, что не пропускает ничего.
Тогда контролируется FDR:

$$k^* = \max\left\{k : p_{(k)} \le \frac{k}{m}\alpha\right\},
\qquad \text{отвергаем } H_{(1)}, \dots, H_{(k^*)}$$

Отвергаются гипотезы **с рангом до $k^*$ включительно**, в том числе те, чей
собственный p-value порог не прошёл. Это свойство процедуры, а не небрежность
реализации.

### Атомы без данных исключаются, а не помечаются незначимыми

```python
if result is None or min(result.n_with, result.n_without) < min_group:
    continue
```

Иначе они раздували бы $m$ и штрафовали поправкой те атомы, по которым данные
есть.

### Хватает ли реплик, чтобы пройти поправку

Тонкий момент, о котором обычно забывают. Минимальный достижимый p-value равен
$1/(1+B)$. Если он сопоставим с порогом поправки, результат решает шум
Монте-Карло, а не данные.

При $B = 2000$ минимум $0.0005$, а порог Бонферрони на 25 тестах — $0.002$.
Пройти могут только реплики с $k \le 3$; при истинной хвостовой вероятности
$0.001$ ожидаемое $k$ равно 2, и $P(K \le 3 \mid \lambda = 2) = 0.857$ — то есть
**14% шанс потерять настоящий эффект** просто на шуме генератора.

```python
def resolution_is_sufficient(n_boot, alpha, tests, correction):
    if n_boot <= 0:
        return False
    threshold = alpha / max(tests, 1) if correction == "bonferroni" else alpha
    return 1.0 / (1 + n_boot) <= threshold / 4.0
```

Требуется запас в четыре раза. Для Бонферрони это даёт правило
$B \ge 4m/\alpha$ (на 45 тестах при $\alpha = 0.05$ — 3600 реплик). Если реплик
мало, таблица печатает предупреждение с нужным числом.

## 12.5. Разбиение истории

### По времени, а не случайно

```python
def split_by_time(frame, holdout=0.3, ts_column="ts"):
    ordered = frame.sort_values(ts_column)
    cut = int(len(ordered) * (1.0 - holdout))
    return ordered.iloc[:cut], ordered.iloc[cut:]
```

`sample_size` монотонно растёт с историей: кандидат 2018 года видит сотню
аналогов, кандидат 2026-го — тысячи. Случайный сплит перемешивает эти режимы и
завышает согласие.

### Граница по барам, а не по календарю

```python
def split_bar(index, frac, min_part=1000):
    cut = int(len(index) * frac)
    if cut < min_part or len(index) - cut < min_part:
        raise ValueError("разбиение даёт слишком короткую часть")
    return index[cut]
```

История монеты неравномерна (у BTC ранние годы разрежены дырами), и календарная
середина дала бы не ту долю данных, которую заявляем.

Функция живёт в общем модуле ровно по одной причине: контрольная модель обязана
делить историю **тем же баром**, что валидация графа, иначе сравнивать их числа
нельзя. Две реализации одной формулы разъехались бы молча.

### Purged walk-forward

Для моделей, обучающихся внутри замера:

```python
def purged_splits(n, folds, gap):
    if folds < 2 or n <= gap * (folds + 2):
        return []                        # фолдов не набирается

    start = n // 2                       # первое обучающее окно — половина истории
    edges = np.linspace(start, n, folds + 1, dtype=int)
    result = []
    for i in range(folds):
        train_end  = int(edges[i])
        test_start = train_end + gap     # ЗАЗОР
        test_end   = int(edges[i + 1])
        if test_end - test_start < gap:
            continue                     # проверочное окно короче зазора — фолд отброшен
        result.append((slice(0, train_end), slice(test_start, test_end)))
    return result
```

```
фолд 1: [────── train ──────]|gap|[test]
фолд 2: [──────── train ────────────]|gap|[test]
фолд 3: [────────── train ──────────────]|gap|[test]
```

**Зазор обязателен.** Метка бара $t$ считается по барам $t+1 \dots t+H$, поэтому
последние $H$ строк обучения «видят» начало проверочного окна. Без пропуска
модель училась бы на исходах, которые она же потом предсказывает.

Это самая частая ошибка в бэктестах на перекрывающихся метках, и она даёт
впечатляющие и ложные числа.

> ⚠️ **Зазор равен горизонту ЗАМЕРА, а не конфигурации.** Захардкоженные 96
> баров для 4-часового замера выбросили бы вшестеро больше нужного и незаметно
> съели мощность.

Расширяющееся окно (а не скользящее) — потому что модель в бою тоже видит всю
доступную историю. Первое обучающее окно — половина истории: на четверти данных
бустинг меряет собственную недоученность.

## 12.6. Метрики качества прогноза

### Directional accuracy

$$\text{acc} = \frac{1}{n}\sum_i \mathbb{1}[\text{side}_i \text{ совпал с исходом}]$$

Нулевая гипотеза 0.5. Значимость — блочным бутстрапом.

### Но 0.5 недостаточно

Если за период holdout рынок рос, стратегия «всегда long» даёт accuracy заметно
выше половины, ничего не зная. Поэтому рядом считается **парная разница**:

$$\Delta_i = \text{hit}_i - \mathbb{1}[\text{up}_i], \qquad H_0: \bar\Delta = 0$$

Для long-кандидатов разница нулевая по построению, то есть весь вклад дают
short-кандидаты — ровно те, где система утверждает нечто против дрейфа.

Критерий «accuracy значимо выше 50%» этим не подменяется, а **дополняется**:
пройденный первый тест при проваленном втором означает, что система переоткрыла
тренд рынка, а не конфигурацию.

### Brier score

$$\text{BS} = \frac{1}{n}\sum_i (p_i - y_i)^2$$

Среднеквадратичная ошибка вероятностного прогноза. Сам по себе не читается —
читается только разница с эталоном:

$$\text{BSS} = 1 - \frac{\text{BS}}{\text{BS}_{\text{ref}}},
\qquad \text{BS}_{\text{ref}} = \text{BS}(\bar{y})$$

Эталон — константный прогноз базовой частотой holdout. Положительный skill —
прогноз лучше константы.

### Калибровка по децилям

Предсказанная доля против фактической:

```python
frame["bin"] = pd.qcut(frame["p"], q=10, labels=False, duplicates="drop")
grouped = frame.groupby("bin").agg(n=..., predicted=("p", "mean"), actual=("y", "mean"))
grouped["gap"] = grouped["actual"] - grouped["predicted"]
```

Бины по **квантилям**, а не по равным интервалам [0, 1]: предсказания системы
сосредоточены вокруг 0.5 (кандидат выпускается при перекосе от 6%), и равные
интервалы дали бы восемь пустых строк из десяти.

$$\text{ECE} = \sum_b \frac{n_b}{n}\left|\text{actual}_b - \text{predicted}_b\right|$$

Идеал калибровки — диагональ, то есть **наклон 1.0** в регрессии факта на
прогноз. Измеренный наклон системы: **0.02–0.07**. Практически это означает, что
предсказанная вероятность не несёт информации о фактической.

### AUC

Считается **по сырым скорам**, до калибровки, и отдельно от accuracy. Две
причины:

- accuracy зависит от порога 0.5, а он у некалиброванной модели произволен;
  AUC от порога не зависит вовсе;
- при вырожденной калибровке accuracy становится равной базовой частоте, и по
  ней уже не отличить «модель ничего не нашла» от «нашла, но сместилась».

## 12.7. Контрольная модель

Задача D1 внешнего аудита: **дело в графе или в самих признаках?**

Граф — это дискретизация 32-мерного вектора в несколько десятков состояний, а
дискретизация всегда теряет информацию. Из того, что система не воспроизводит
свой эффект, не следует, где потолок.

### Конструкция

Градиентный бустинг на тех же 32 признаках, с той же целевой, на том же
разбиении, без всякого графа.

```python
HistGradientBoostingClassifier(
    max_iter=300, learning_rate=0.05, max_depth=4,
    min_samples_leaf=200, l2_regularization=1.0,
    early_stopping=False,          # ранняя остановка по случайному срезу — протечка
    random_state=seed,
)
```

Гиперпараметры объявлены заранее и под метрику **не подбираются**: подбор
гиперпараметров под целевую метрику — ровно тот способ найти эффект, которого
нет.

Ранняя остановка выключена намеренно: её внутренний случайный срез на временном
ряде — протечка.

### Контроль честнее проверяемой системы

Деревьям безразличен масштаб, поэтому у контрольной модели **нет** look-ahead
нормировки `robust_scale_params`, который остаётся в боевом расчёте графа
(глава 5.6).

Это правильная сторона для ошибки: если сигнала нет даже у более честной модели,
вывод крепче.

### Изотоническая калибровка

```python
tail = int(n * CALIBRATION_TAIL)          # 20% обучающей части
head_end = max(1, n - tail - gap)
model.fit(x_train[:head_end], y_train[:head_end])
iso.fit(model.predict_proba(x_train[n - tail:])[:, 1], y_train[n - tail:])
```

Модель учится на голове, изотоника — на хвосте, отделённом тем же зазором, и ни
одна не видит проверочного окна.

Сырые вероятности бустинга смещены, а Brier и калибровочная таблица без этого
мерили бы смещение, а не информативность.

**Возвращаются оба вектора, и это необходимость.** Изотоника монотонна и ранга
обычно не меняет, но при отсутствии монотонной связи на калибровочном хвосте она
схлопывает прогноз в **константу**. Это её честный ответ «связи нет», но по
константе уже нельзя отличить «модель не различает» от «различает, но смещена».
Поэтому калиброванные числа идут в Brier и в калибровочную таблицу, а
различающая способность (AUC, разрез по уверенности) считается по сырым.

### Результат

Критерий не прошёл ни на одной из четырёх монет: AUC 0.504–0.536, Brier skill
отрицателен у трёх из четырёх, у BTCUSDT разница с «всегда long» значимо
отрицательна.

Вывод по объявленной заранее таблице: **потолок в признаках**, граф ни при чём.

## 12.8. Градация: более сильная форма гипотезы

`lift.py` отвечает на вопрос «отличается ли исход там, где атом сработал». Это
самая бедная возможная формулировка: `in_unfilled_fvg` — булево «цена внутри
незакрытого имбаланса», и вся градация (свежесть зоны, её размер, доля закрытого
разрыва, номер касания) в один бит не влезает.

Постановка `gradation.py`: разбить непрерывный признак на квантильные бины и
проверить не разницу двух групп, а **монотонность тренда** — обобщённый тест
Кохрана–Армитажа.

$$T = \sum_i t_i \left(r_i - n_i \mu\right), \qquad
\operatorname{Var} = \sigma^2\left[\sum_i n_i t_i^2 -
\frac{\left(\sum_i n_i t_i\right)^2}{N}\right], \qquad
z = \frac{T}{\sqrt{\operatorname{Var}}}$$

где $t_i$ — оценка группы (номер бина; бины равнонаполненные, поэтому любая
монотонная шкала даёт тот же знак), $n_i$ — объём группы, $r_i$ — **сумма**
метрики в ней, $\mu$ — общее среднее, $\sigma^2$ — общая дисперсия метрики
(population, `ddof=0`).

**Обобщение здесь именно в $\sigma^2$.** Классический Кохран–Армитаж
сформулирован для бинарной метрики и берёт $\sigma^2 = \mu(1-\mu)$ — дисперсию
Бернулли. Это частный случай общей формулы: для метрики из $\{0,1\}$
$\mathbb{E}[(x-\mu)^2] = \mu(1-\mu)$ **точно**, то есть на бинарной цели замена
не меняет поведение ни на бит. Для непрерывной цели (`range_ratio`) берётся её
фактическая дисперсия, и тест остаётся тем же линейным трендовым контрастом —
эквивалентом линейного контраста ANOVA.

Обобщение потребовалось для гейта G: он обязан уметь непрерывную цель, а не
только `is_up`, на которой мерился Fear & Greed.

«Чем свежее зона, тем выше доля роста» — гораздо более сильное свидетельство,
чем «за порогом доля выше»: один удачно попавший порог объясняется случайностью
легко, монотонность по пяти бинам — трудно.

Отличие от двухвыборочного z-теста принципиальное: тот спрашивает «разошлись ли
две группы», этот — «идёт ли метрика по возрастанию оценки». Немонотонный
профиль с разошедшимися краями первый находит, второй штрафует.

Поэтому значимости мало: `TrendResult.confirmed` требует ещё и монотонности
долей по бинам, и сохранения знака `spread` на holdout при сопоставимой
величине (отношение в диапазоне 0.5–2.0) — те же условия, что у лифта по
атомам.

Пять бинов по умолчанию: терцилей мало, чтобы увидеть монотонность, а децили на
выборке в 30 тысяч кандидатов с учётом перекрытия горизонтов дают меньше сотни
независимых наблюдений на бин.

Отдельное достоинство метода: признаки для него включать в модель **не нужно** —
значения считаются на барах кандидатов и приджойниваются. Поэтому замер не
зависит от калибровки дробления состояний и запускается на работающей системе.

## 12.9. Out-of-sample R² и его знаменатель

Для непрерывной цели (размах) метрика другая.

$$R^2_{\text{OOS}} = 1 -
\frac{\sum_i (y_i - \hat{y}_i)^2}{\sum_i (y_i - r_i)^2}$$

где $r_i$ — **опорный прогноз**. И вот его выбор — источник тихой ошибки.

> ⚠️ **Считать R² относительно среднего проверочного окна — подглядывание.** На
> нестационарной цели знание её собственного уровня уже даёт $R^2 > 0$ даром.

Правильный знаменатель — среднее **обучающей** части. Разница двух знаменателей
печатается отдельной строкой («дрейф среднего»):

$$\text{drift} = R^2\left(\bar{y}_{\text{test}} \text{ как прогноз},\
\bar{y}_{\text{train}} \text{ как опора}\right)$$

Она показывает, насколько цель нестационарна, и заодно доказывает, что
подглядывание было бы не безобидным.

Величина $R^2_{\text{OOS}}$ может быть **отрицательной**, и это не ошибка, а
честный ответ «модель хуже константы, известной до начала окна».

### Сравнение двух моделей

Знаменатель у обеих один и тот же, поэтому приращение равно **сумме** построчных
разностей квадратов ошибок, делённой на этот знаменатель:

$$\Delta R^2 = \frac{\sum_i \left(e_i^{\text{base}}\right)^2 -
\left(e_i^{\text{full}}\right)^2}{\text{SST}},
\qquad \text{SST} = \sum_i \left(y_i - \bar y_{\text{train}}\right)^2$$

```python
sst   = base.total_sum_of_squares
diff  = base.squared_errors - full.squared_errors
delta = diff.sum() / sst
p_value = block_mean_p(diff, block_length, n_boot, rng)
```

Отсюда и способ значимости: блочный бутстрап по ряду **построчных разностей**,
$H_0$: «модель full в среднем не точнее». Знак среднего разностей и знак
$\Delta R^2$ совпадают всегда — делитель SST положителен и от реплики не
зависит, — поэтому тест на «среднее ряда положительно» и есть тест на
приращение.

Пересобирается именно разность, а не предиктор: обе модели уже посчитаны на
одних и тех же строках, и вопрос стоит про их сравнение, а не про связь величины
с целью.

Равенство строк проверяется явно:

```python
def assert_aligned(self, other):
    if self.n != other.n or not np.array_equal(self.fold, other.fold):
        raise ValueError("две модели посчитаны на разных строках — "
                         "приращение R² между ними не имеет смысла")
```

### Частный R² через остатки

Для одиночного предиктора сверх матричного бенчмарка:

$$\Delta R^2 = (1 - R^2_{\text{base}}) \cdot \operatorname{corr}(y^\perp, p^\perp)^2$$

где $\perp$ — остаток после проекции на бенчмарк со свободным членом.

Это то же самое, что разность $R^2$ двух регрессий, но пересчитывать регрессию на
каждой реплике не нужно: остаток цели считается один раз, а остаток предиктора —
одним умножением матриц на весь чанк реплик.

Проекция — через ортонормированный базис (QR-разложение):

```python
q, _ = np.linalg.qr(np.column_stack([np.ones(n), benchmark]))
y_perp = rank_y - (rank_y @ q) @ q.T
```

Для одномерного бенчмарка есть замкнутая форма через матрицу корреляций:

$$R^2(y \sim b, p) = \frac{r_{yb}^2 + r_{yp}^2 - 2 r_{yb} r_{yp} r_{bp}}
{1 - r_{bp}^2}$$

$$r_{yp \cdot b} = \frac{r_{yp} - r_{yb} r_{bp}}
{\sqrt{(1 - r_{yb}^2)(1 - r_{bp}^2)}}$$

### Ранги или логарифм

Дисциплина зависит от того, где считается величина.

**In-sample (частный R²) — на рангах.** `range_ratio` тяжелохвостый, Pearson на
сырых значениях обманывается выбросами.

**Out-of-sample — на логарифме.** Ранг **не переносится через границу фолда**:
ранг проверочной строки зависит от остальных проверочных строк, то есть от
будущего внутри окна. Логарифм — фиксированное монотонное преобразование,
считается построчно и протечки не создаёт вовсе.

Тонкость при матричном бенчмарке: ранжируются цель, предиктор и колонки
волатильности (все тяжелохвостые), но **не** гармоники часа и флаг выходных —
ранг синуса не синус, и ранжирование сломало бы ту конструкцию, ради которой
колонки заведены.

## 12.10. Значимость — это ещё не результат

Отдельный урок, закреплённый в коде.

При $n_{\text{эфф}}$ в тысячи минимальный детектируемый $\Delta R^2$ — порядка
$10^{-4}$. То есть значимость достигается на практически ничтожных величинах.

Живой пример: раздел 36 журнала зафиксировал $\Delta R^2 = 0.011$ при
$p \le 0.002$ — «надёжно значимый» эффект размером в 1% дисперсии. Через четыре
дня выяснилось, что и он держится на неполном бенчмарке.

Отсюда правило: **ни один критерий проекта не состоит из одного порога p.**
Рядом всегда стоит порог практической величины.

Пример полного критерия (гейт модели размаха):

```python
MIN_DELTA_R2 = 0.02          # практическая величина
MAX_COVERAGE_ERROR = 0.05    # калибровка

if not (gain.delta >= MIN_DELTA_R2 and gain.p_value <= 0.05):
    failures.append(...)
if not (p_better <= 0.05 and rho > rho_bench):
    failures.append(...)
if not (worst <= MAX_COVERAGE_ERROR):
    failures.append(...)
```

## 12.11. Бенчмарк обязан быть нетривиальным

Второй методологический урок, стоивший проекту отозванного результата.

Половина эффектов, которые проект видел, исчезала при замене нулевого бенчмарка
на честный.

| Задача | Наивный бенчмарк | Правильный |
|---|---|---|
| Направление | «монетка» (0.5) | «всегда long» |
| Размах | ноль | HAR-RV + час дня + выходные |
| Внешний источник | «коррелирует с целью» | «добавляет сверх `rv`» |

### История отзыва гейта деривативов

Открытый интерес (`oi_chg_1h`) проходил гейт «предсказывает размах сверх
скользящей `rv`» устойчиво на трёх монетах с $\Delta R^2$ 0.002–0.011. Числа
воспроизводятся.

Но бенчмарк был неполон: **в скользящей `rv` нет времени суток**, а по сессиям
меняются и открытый интерес, и размах.

С бенчмарком «HAR-RV + час дня» медиана $\Delta R^2$ падает до 0.0008, **ни одна
из 54 ячеек** не достаёт до порога практической величины 0.005, и 63% эффекта
съедает сезонность. Оба условия отзыва, объявленные в ТЗ, выполнились вместе, и
гейт был **отозван**.

> Отзыв собственного результата — такая же штатная работа механизма, как
> отвержение чужой гипотезы. Читать раздел 36 журнала без 47.4 нельзя: его числа
> верны, неверен был его знаменатель.

### Два способа сравнить с бенчмарком

**«Источник сильнее бенчмарка»** ($|\rho_a| > |\rho_b|$) — `paired_diff_p`.

**«Источник добавляет к бенчмарку»** (частная корреляция) — `partial_r2_gain`.

Второй обязателен для источника, который может дойти до значимого собственного
$\rho$: проиграть сопернику, сильному **по конструкции цели** (тот же знаменатель
ATR, что у `rv`), было бы отвержением по артефакту нормировки, а не по существу.

## 12.11а. Бенчмарк обязан знать о НАСТОЯЩЕМ столько же, сколько модель

Третий методологический урок, и он дороже двух предыдущих: он ставит оговорку
к единственному положительному результату проекта. Обнаружен 2026-08-24
суррогатным прогоном (раздел 12.14), журнал генератора — раздел 56.

Раздел 12.11 требует, чтобы бенчмарк был **нетривиален**. Этого мало. Он
обязан быть ещё и **равноинформированным о моменте $t$**.

### Механизм

Цель размаха — отношение, и в логарифмах она распадается на разность:

$$\log(\text{range\_ratio}) = \log(\text{будущий размах}) - \log(\text{знаменатель})$$

Знаменатель — ATR, посчитанный **на баре $t$**. Он известен, никакого будущего
в нём нет. Но он входит в цель, а значит объясняет часть её дисперсии — и тот,
кто знает его лучше, получит более высокий $R^2$, ничего не зная о будущем.

При нормировке `atr14` окно знаменателя — 14 баров (3.5 часа). Самое короткое
окно бенчмарка B2 — 96 баров (сутки). Модель видит 32 признака, среди них
`atr_rank` и другие короткие; бенчмарк не видит ничего короче суток. Разрыв в
информации о настоящем встроен в конструкцию.

### Как это выглядит в чистом виде

На суррогатных данных, где будущее непредсказуемо в принципе, условное
среднее будущего размаха почти постоянно — и вся дисперсия цели приходится на
знаменатель:

| данные | $R^2$(B2) | $R^2$(модели) | $\Delta R^2$ |
|---|---|---|---|
| реальные, BTC 24h/atr14 | +0.209 | +0.279 | +0.070 |
| суррогат IAAFT | +0.014 | +0.224 | **+0.210** |
| суррогат, нормировка `atr_h` | −0.014 | −0.001 | +0.013 |
| суррогат, знаменатель В бенчмарке | +0.234 | +0.227 | **−0.007** |

Третья строка: если окно знаменателя равно горизонту (того же порядка, что у
HAR), эффект почти исчезает. Четвёртая: если отдать знаменатель бенчмарку,
эффект исчезает целиком и становится отрицательным. Механизм объясняет
результат полностью.

### Сколько от реального результата этим объясняется

Тот же диагностический прогон на настоящих данных, BTC и SOL, два горизонта,
обе нормировки:

| ячейка | $\Delta R^2$ с B2 | с B2 + знаменатель | осталось |
|---|---|---|---|
| BTC 24h atr14 | +0.070 | +0.024 | 35% |
| BTC 24h atr_h | +0.064 | +0.049 | 77% |
| BTC 4h atr14 | +0.040 | +0.014 | 36% |
| BTC 4h atr_h | +0.039 | +0.015 | 38% |
| SOL 24h atr14 | +0.077 | +0.027 | 36% |
| SOL 24h atr_h | +0.034 | +0.019 | 55% |
| SOL 4h atr14 | +0.039 | +0.023 | 59% |
| SOL 4h atr_h | +0.039 | +0.024 | 62% |

**Медиана — 46%.** Все три условия критерия главы 13 выдерживают 3 ячейки из
8 против 7 из 8 у штатного бенчмарка.

### Что из этого следует

Вердикт главы 13 формально не отменяется: критерий был заявлен против B2 и
против него пройден, а условия не пересматриваются по итогам — в том числе
когда пересмотр был бы в сторону строгости.

Меняется то, что число **значит**. «Приращение +0.02…+0.10 сверх бенчмарка»
нельзя читать как «настолько лучше предсказывает будущий размах»: около
половины величины — это «модель знает текущий ATR, а бенчмарк знает только
суточный».

> ⚠️ **Ломается молча.** Разница в информации о НАСТОЯЩЕМ выглядит в $R^2$
> ровно так же, как разница в способности предсказывать БУДУЩЕЕ. Ни блочный
> бутстрап, ни отложенная часть, ни поправка на множественность их не
> различают: все три проверки эффект подтверждают. Различает единственная
> процедура — прогон на данных, где будущего нет.

Правило, которое отсюда следует и которое стоит применять ко всякому будущему
замеру: **если цель содержит величину, известную на баре $t$, бенчмарк обязан
её знать.** Иначе замер меряет информационную асимметрию под видом
предсказательной силы.

## 12.12. Критерий объявляется до запуска

Инвариант 5 проекта. Формулируется письменно, в ТЗ замера, до первой строки

Пример (контрольная модель):

> **«Сигнал есть»** означает: на отложенной части directional accuracy значимо
> выше 0.5 по блочному бутстрапу **И** парная разница с бенчмарком «всегда long»
> значимо положительна, **И** Brier skill относительно константного прогноза
> положителен, — на двух монетах из трёх и на двух разных зёрнах бустинга.
>
> Дополнительно, но не как часть критерия: различает ли модель собственную
> уверенность.

Три свойства такого критерия:

1. его нельзя подвинуть после того, как увидел числа;
2. он требует воспроизведения (две монеты, два зерна);
3. «дополнительно, но не как часть критерия» отделяет наблюдения от решений.

Плюс правило репликации: **шесть монет — это не шесть независимых наблюдений**.
BTC, ETH и SOL коррелированы выше 0.8, и расширение списка монет ради
«подтвердилось на трёх из трёх» запрещено внутренними правилами проекта.

Для общерыночных рядов (FGI — один ряд на все монеты) устойчивость проверяется
**разбиением по эпохам**, а не по монетам: «знак совпал на трёх монетах» для
такого источника не подтверждение, а один замер, показанный трижды.

И отдельно — требование **двух моделей состояний**: выборка кандидатов
порождается моделью, а число состояний невоспроизводимо (глава 7.9). Замер на
одной модели мерил бы реализацию процедуры.

## 12.12а. Суррогатный прогон: сколько находок делает сама процедура

Блочный бутстрап отвечает на вопрос «значим ли **этот** эффект». Он не
отвечает на другой: **сколько эффектов такого размера порождает сама
процедура** — от признаков и разбиения до критерия с его условиями.

Разница не схоластическая. У отрицательного результата цена ошибки низкая:
анти-консервативный тест делает отрицательный вывод только надёжнее. У
положительного — наоборот, и проверить его нечем, кроме прогона того же кода
на данных, где предсказывать заведомо нечего.

### Устройство суррогата

`btcproc/analysis/surrogate.py`, три способа, все — **перестановки целых
баров**:

* **IAAFT** (iterative amplitude adjusted Fourier transform, Schreiber &
  Schmitz 1996) — сохраняет амплитудный спектр ряда доходностей и их
  маргинальное распределение, разрушая нелинейную структуру: кластеризацию
  волатильности и суточный профиль. Самый жёсткий;
* **блочная перестановка** блоками в горизонт — волатильность внутри блока
  сохраняется, на больших масштабах разрушается;
* **сезонная перестановка** внутри бина «час дня × день недели» — сохраняет
  суточный профиль полностью, разрушает всё остальное. Нужна там, где
  сезонность разрушать нельзя (глава 12.11: без часа дня бенчмарк не
  бенчмарк).

Проверка на боевых данных BTC: автокорреляция $|r|$ на лаге 1 — 0.323 у
реального ряда, 0.001 у IAAFT, 0.319 у блочного. Распределение доходностей у
IAAFT совпадает с исходным поточечно.

### Ловушка, на которой эта конструкция уже ошиблась

Суррогат порождает **один ряд** — доходности закрытий. А признаки и цель
считаются из четырёх колонок OHLC плюс объёма. Способ достроить остальное
решает, что именно окажется нулёвкой.

Первая версия модуля брала геометрию бара ($H/C$, $L/C$) у донора **той же
позиции** — «чтобы сохранить суточный профиль размаха». Цель `range_ratio`
считается ровно из `high`/`low`, значит она наследовала реальную кластеризацию
волатильности; часть признаков (`atr_rank`, положение в диапазоне) наследовала
её же. Суррогат становился данными, на которых предсказывать ЕСТЬ что, и
«ложное срабатывание» на нём не означало бы ничего.

Правильная конструкция: из алгоритма извлекается **перестановка** $\pi$, и
вместе с доходностью в новую позицию переезжает весь бар донора — геометрия,
объём, число сделок, объём тейкеров. Каждый бар суррогата — настоящий бар
настоящего рынка; разрушен ровно их порядок во времени.

### Что показал прогон

Первый же суррогат дал $\Delta R^2 = +0.21$ — втрое больше, чем реальные
данные, — и прошёл все три условия критерия. На двадцати репликах картина
подтвердилась: критерий проходят **19 реплик из 20** у IAAFT (медиана
$\Delta R^2 = +0.217$) и **17 из 20** у блочной перестановки (медиана
$+0.119$) при заявленном пороге «не более 0.10 реплик и не более 0.005
медианы». Два способа различаются ровно так, как должны — блочный мягче, и
эффект у него вдвое меньше, — но оба на два порядка выше порога.

Разбор механизма занял больше времени, чем сам прогон, и привёл к разделу
12.11а: дело оказалось не в процедуре вообще, а в конкретной информационной
асимметрии между моделью и бенчмарком.

Это и есть штатная работа суррогата: он не выносит вердикт, он показывает, что
вердикт надо перечитать.

## 12.14. Резюме главы

Вся измерительная инфраструктура проекта построена вокруг одного факта:
наблюдения зависимы, и наивная статистика завышает уверенность втрое.

Пять правил, которые стоит унести из этой главы в любой похожий проект:

1. **Считайте зависимость.** Блочный бутстрап, длина блока — из данных, а не из
   горизонта в барах.
2. **Бенчмарк нетривиален.** «Лучше нуля» ничего не значит; сравнивайте с тем,
   что уже есть, включая календарь.
3. **Значимость — не результат.** Рядом обязан стоять порог практической
   величины.
4. **Критерий объявляется письменно до запуска** и требует воспроизведения.
5. **Разбиение по времени, с зазором в горизонт.** И знаменатель $R^2$ — среднее
   обучающей части, никогда не проверочной.

Следующая глава — про единственную конструкцию, которая через все эти фильтры
прошла.
