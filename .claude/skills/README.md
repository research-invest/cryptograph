# Скиллы crypto-graph

Скилл — это оформленная инструкция для Claude Code: пошаговая процедура,
которую он загружает и выполняет вместо импровизации, когда запрос попадает
в её область. Скиллы лежат по одному в каталоге (`SKILL.md` + при
необходимости `references/`, `scripts/`), их не нужно ничего «включать» —
Claude сам подхватывает список доступных скиллов в начале сессии.

## Как вызвать

Два равнозначных способа:

1. **Явно, слэш-командой** — `/add-symbol` или `/system-sanity-check`.
   Подойдёт, когда точно знаешь, какая процедура нужна.
2. **Обычным языком** — просто опиши, что нужно («заведи SUIUSDT», «кандидаты
   пропали, проверь плиз»). Claude сравнивает запрос с полем `description`
   в шапке каждого `SKILL.md` и сам решает, подходит ли скилл — отдельно
   вызывать его не нужно, докидывать «используй скилл X» тоже не обязательно,
   хотя это работает и однозначно быстрее, если формулировка запроса
   неочевидна.

Скилл не обязан выполняться целиком «в одно касание»: `add-symbol`, например,
рассчитан на диалог в несколько заходов (фазы 1–7 с гейтами между ними) — это
нормально, не повод искать более короткий путь.

## Какой скилл когда

| Ситуация | Скилл | Что получишь |
|---|---|---|
| «Добавь монету SUIUSDT», «заведи новую пару», «выкати монету на прод» | `/add-symbol` | Пошаговое заведение монеты в обоих проектах: реестр → история → граф состояний → профиль оценки → sanity-якорь → тесты → отправка кандидатов → (по отдельной команде) деплой. Каждая фаза с гейтом — не проходит гейт, не идём дальше. |
| «Почему у монеты всё WEAK», «пять состояний вместо сорока» — уже ПОСЛЕ того, как монета заведена | `/add-symbol` | В `references/troubleshooting.md` — типовые поломки по фазам с диагнозом и лечением, без повторного прохождения всей процедуры. |
| «Кандидаты пропали», «после train ничего нет», «live не шлёт», «в дашборде по нулям», «у одной монеты кандидаты есть, у других нет» | `/system-sanity-check` (категория A) | Пошаговая проверка логов, расписания, БД и исторического базового уровня — с чёткими критериями, когда это норма (train `--no-emit`, тихий рынок, фильтр по качеству, первичный train новой монеты), а когда действительно повод чинить код. |
| «Граф состояний развалился», «узлы висят отдельно от остального графа», «изолированные состояния» | `/system-sanity-check` (категория B) | Объяснение механизма (обрезка рёбер на клиенте по `topEdges`) + способ за минуту отличить реальную изоляцию состояния от артефакта отображения. |
| Любое «всё ли в порядке с системой» без конкретного симптома | `/system-sanity-check` | Общее правило скилла — не выносить вердикт по одному взгляду на экран, требовать факт из БД/лога под каждый вывод. |

## Что важно про оба скилла

- Оба обращаются к **боевому проду** (`ssh vps@162.248.225.60`) и к
  **локальному Docker-стенду** — команды в скиллах написаны так, что
  работают в обоих окружениях, разница обычно в паре строк (наличие `ssh
  vps@... "..."` снаружи команды, `docker exec btc_postgres` против `docker
  compose exec -T postgres`).
- Оба требуют **факта, а не впечатления**: конкретный traceback, конкретная
  строка в БД, конкретный результат прямого теста — а не «выглядит так, как
  будто…». Это не стиль написания ради стиля: оба скилла родились из
  реальных случаев, когда система молча вела себя штатно, а на глаз это
  читалось как поломка.
- Оба **не деплоят и не чинят прод сами по себе**: `add-symbol` останавливает
  выкатку на фазе 7 до явной команды пользователя, `system-sanity-check` —
  чисто диагностический, правки по его результатам (если понадобятся) —
  отдельный шаг за пределами скилла.

## Структура каталога

```
.claude/skills/
├── README.md                      — этот файл
├── add-symbol/
│   ├── SKILL.md                   — сама процедура, фазы 0–7
│   ├── references/troubleshooting.md  — диагностика по фазам постфактум
│   └── scripts/make_sanity_anchor.py  — вызывается из фазы 5
└── system-sanity-check/
    └── SKILL.md                   — категории A (кандидаты) и B (граф)
```

Новый скилл заводится тем же способом: каталог с `SKILL.md`, шапка с `name`
и `description` — по описанию Claude и решает, когда его предлагать.
